# Packages

A Sonata package is a Git repository that is itself a Sonata project: it contains a
`.sonata/project.luau` and the entrypoint it names. There is no central registry; you depend
on a repository by its URL.

## Adding a dependency

```sh
sn pkg add github.com/acme/json5
sn pkg add https://github.com/acme/json5.git#v2.0.0
```

`sn pkg add` clones the repository, checks that it is a valid project, installs it (and
whatever it depends on) into `.sonata/deps/`, and adds it to the manifest:

```luau
dependencies = {
    { name = "json5", url = "https://github.com/acme/json5", ref = "v2.0.0" },
},
```

Then require it by name:

```luau
local json5 = require("@json5")
```

### Dependency specs

A spec is `<url>[#<ref>]`:

- **`url`**: anything `git clone` accepts. A URL that starts with a host name, such as
  `github.com/user/repo`, gets `https://` added. SSH URLs (`git@github.com:user/repo.git`) and
  local paths are left as they are.
- **`ref`**: a branch, tag or commit hash. Without it, the remote's default branch is used.

The dependency's **name** comes from the repository name: the last path segment, without
`.git`, with every character that isn't a letter, digit or `_` turned into `_` (and a `_` added
in front of a leading digit). `github.com/acme/my-lib` becomes `my_lib`. To choose another
name, edit the manifest or use a file with `--read` (below).

### Adding many at once

Give several specs, or list them in a Luau file and pass it with `--read`:

```luau
-- deps.luau
return {
    "https://github.com/acme/json5.git#v2.0.0",           -- name derived from the URL
    cli = "https://github.com/acme/command-line.git",       -- the key is the name
    { name = "log", url = "https://github.com/acme/logging.git", ref = "main" },
}
```

```sh
sn pkg add --read deps.luau
```

## Installing what the manifest lists

After cloning a project, install its dependencies with:

```sh
sn pkg add --install       # or: sn pkg add -i
```

`sn run --install` and `sn build --install` do the same before running or building. Without
`--install`, running a project whose dependencies are missing fails with
`missing dependencies: ... (pass --install to fetch them)`; Sonata never downloads anything
unless you ask it to.

## Layout and the lock file

```
project/
└── .sonata/
    ├── project.luau
    ├── lock.luau        what was installed: url, ref and exact commit
    └── deps/
        ├── json5/       a dependency, checked out without its .git folder
        ├── cli/
        └── .staging/    scratch space while installing, always cleaned up
```

Everything inside `.sonata/deps` is owned by the package manager. Don't edit it; your changes
would be lost on the next update. You will usually want to add `.sonata/deps/` to your
`.gitignore` and commit `lock.luau`.

The lock file records the exact commit of every installed package:

```luau
--[[
    This file is automatically generated by Sonata.
    DO NOT EDIT MANUALLY - Changes will be overwritten.
]]

return {
    version = 1,
    packages = {
        json5 = {
            url = "https://github.com/acme/json5",
            ref = "v2.0.0",
            commit = "3f2a9c...",
        },
    },
}
```

When a package is missing from `deps/` but the lock entry still matches the manifest (same
URL and ref), installing fetches **the locked commit**, not whatever the branch points to now.
This makes installs reproducible. Only `sn pkg update` moves packages forward.

## Dependencies of dependencies

Packages can have dependencies of their own. All of them are installed **flat** into the root
project's `.sonata/deps`, so every package name refers to exactly one folder.

If two packages ask for the same name from different sources:

- if the root project lists that name itself, the root's choice wins (Sonata prints a note);
- otherwise installation fails with a `dependency conflict` error. Add the package to your own
  manifest to choose one.

Inside a dependency, `require("@name")` works for the packages that dependency's own manifest
lists, even if your project doesn't mention them.

## Updating

```sh
sn pkg update              # re-fetch every package from its ref
sn pkg update json5 cli    # only these
```

Updating ignores the lock file, fetches each package's ref again, and records the new commits.
The command reports what changed (`updated json5: 3f2a9c1e02 -> 8b1d44f0aa`).

## Removing

```sh
sn pkg remove json5
```

This removes `json5` from the manifest and deletes its folder, together with every package
that only `json5` needed. A package that something else still needs is kept, and the command
says who needs it.

| Option | Effect |
|---|---|
| `--nodep`, `-nd` | Only delete the named packages, not the dependencies they brought in. |
| `--nomanifest`, `-nm` | Delete the folders but leave the manifest and lock file alone. `sn pkg add -i` brings them back exactly as locked. |
| `'*'` | Remove every package. Quote it so the shell doesn't expand it. |

## Inspecting

```sh
sn pkg status
```

lists the project, the lock file, and every package with its version, URL, ref, locked commit,
path, what it depends on and what uses it. Each package gets a state:

| State | Meaning |
|---|---|
| `ok` | Installed and locked. |
| `missing` | Declared but not installed. Run `sn pkg add -i`. |
| `mismatch` | The lock file recorded a different URL or ref than the one declared now. |
| `extraneous` | Installed, but nothing needs it any more. |
| `unlocked` | Installed, but its commit is unknown (not in the lock file). |

`sn pkg status --lua` prints the same data as a Luau table, for scripts. `--nodep` lists only
the project's direct dependencies.

## How a package is installed

1. The repository is cloned into `.sonata/deps/.staging/<random>`. The `git` executable on
   your `PATH` is used; builds compiled with libgit2 support fall back to it.
2. The clone is opened as a Sonata project. If it isn't a valid one, nothing is installed.
3. Its `.git` folder is removed and it is moved to `.sonata/deps/<name>`.
4. The same happens for whatever it depends on.

A failed install never leaves a half-written package behind: the previous version stays in
place. Git runs with `GIT_TERMINAL_PROMPT=0`, so a private repository fails instead of waiting
for a password.

## From scripts

[`@sonata/sonata`](../api/module/sonata.md) exposes the package manager to Luau:
`sonata.install()`, `sonata.add()`, `sonata.remove()`, and so on.
